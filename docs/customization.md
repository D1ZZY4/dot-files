# Customization Guide

This setup is edited in small, focused modules. Prefer the preference files below for everyday changes; edit TOML or Fish sources when you need deeper control.

## Preference files

Three plain-text files control the most common options. Each supports `#` comments. After editing, apply changes as noted.

| File | Purpose | Apply changes |
|------|---------|---------------|
| `~/.config/starship/style` | Prompt separator style `1`–`5` | `dot-files --edit style` or new shell |
| `~/.config/starship/color` | Palette name (`moonlight`, `catppuccin-macchiato`, `catppuccin-mocha`) | `dot-files --edit color` or new shell |
| `~/.config/starship/username` | Custom Fastfetch welcome name | `dot-files --edit username` or `fastfetch-apply-welcome` |
| `~/.config/starship/ls-style` | eza `ls` output style (1–6) | `dot-files --ls-style <N>` or new shell |
| `~/.config/starship/ll-style` | eza `ll` output style (1–6) | `dot-files --ll-style <N>` or new shell |
| `~/.config/starship/ls-group` | Group directories first (`on`/`off`) | `dot-files --ls-group on|off` or new shell |
| `~/.config/starship/modules.conf` | Enabled Starship modules | `dot-files --edit modules` or `--enable-module`/`--disable-module` |
| `~/.config/starship/dev-tools.toml` | Dev Tools visibility | `dot-files --edit dev-tools` or `--dev-tools toggle <tool>` |

**System username (default):** leave `username` empty (comments only). Fastfetch shows `Welcome, {user-name}!`.

**Custom welcome name:** add one line, for example `Alex`, then run:

```fish
dot-files --edit username
```

Or use the helper command:

```fish
dot-files --username "Alex"
dot-files --username reset   # back to system username
```

Equivalent flags: `dot-files --style 5`, `dot-files --color moonlight`.

## The `--edit` workflow

Open a preference file in `$EDITOR`. After the editor exits, the file is immediately
applied:

```fish
dot-files --edit style     # rebuild prompt and show a preview
dot-files --edit color     # rebuild prompt and show a preview
dot-files --edit modules   # rebuild prompt and show a preview
dot-files --edit username  # apply Fastfetch welcome
dot-files --edit dev-tools # edit visibility; changes apply next startup (or run reload)
```

- **style / color / modules** — rebuilds the Starship config after the editor exits, then shows a prompt preview.
- **username** — runs `fastfetch-apply-welcome` after the editor exits.
- **dev-tools** — reminders that changes apply on next startup; run `dot-files --dev-tools reload` to apply now without `exec fish`.

## Persistent PATH

`fish_user_paths` is a Fish universal variable that Fish automatically prepends
to `PATH` on every shell startup. It is the recommended place for tool-managed
directories (fnm, mise, cargo, go, Python venvs, etc.).

The setup creates this variable via `conf.d/15-paths.fish` if it does not yet exist:

```fish
set -q fish_user_paths; or set -U fish_user_paths
```

Append entries with `set -U`; deduplication is handled by Fish:

```fish
set -U fish_user_paths ~/.cargo/bin $fish_user_paths
set -U fish_user_paths ~/go/bin $fish_user_paths
set -U fish_user_paths ~/.local/bin $fish_user_paths
```

A list of recommended PATH entries for common CachyOS tools is in
`config/fish/conf.d/15-paths.fish`.

## Dev Tools block

The Dev Tools block is generated by:

```text
~/.config/fastfetch/dev-tools.fish
```

It lists tools found on `PATH` (Node.js, package managers, Python, Git, Docker, and others). Missing tools are omitted.

To add a tool, edit `dev-tools.fish`: add an `__tool_line` entry in the appropriate section.

Python versions are discovered from executables named `python3.x` on `PATH`.

### Toggling tools

Create the visibility config, then toggle individual tools:

```fish
dot-files --dev-tools init
dot-files --dev-tools toggle docker
```

The config lives in `~/.config/starship/dev-tools.toml`. Set any `<tool> = false` to hide it. Tools that are not installed are omitted regardless.

### Hot reload

`dot-files --dev-tools reload` re-reads the visibility config and re-renders the
Dev Tools block in the current terminal. No `exec fish` needed.

```fish
# toggle a tool and apply immediately
dot-files --dev-tools toggle docker
dot-files --dev-tools reload
```

### Doctor

`dot-files --doctor` runs read-only sanity checks and prints one line per check.

```
dot-files doctor:
[OK] starship is on PATH
[OK] fastfetch is on PATH
[OK] fish config loads cleanly
[WARN] color 'foobar' does not match any theme in colors/
[OK] modules.conf references only known modules
[OK] dev-tools.toml keys match known tools
[OK] starship.toml exists
[FAIL] fastfetch config.jsonc not found at ~/.config/fastfetch/config.jsonc
```

Exit 0 if all checks pass (no FAIL); exit 1 if any FAIL is present. Does not write to any file.

### Status

`dot-files --status` reports the git state of the installed dotfiles.

```text
Repo: ~/.local/share/dotfiles
Branch: main
No modified files.
No untracked files under config/.
Installed dotfiles are up to date.
```

If installed via copy (no git repo): prints "Installed via copy or unknown source. Cannot determine status."

## Fish

Fish files install under:

```text
~/.config/fish/
```

| Path | Role |
|------|------|
| `conf.d/` | Startup fragments (loaded automatically) |
| `functions/` | Commands such as `dot-files`, `ls`, `nvm` |
| `completions/` | Tab completions for `dot-files` |
| `config.fish` | Minimal entry point |

Recommended practice:

- Environment variables in `conf.d/`
- Reusable commands in `functions/`
- Keep `config.fish` minimal

## Starship

Modules live under:

```text
~/.config/starship/modules/
```

After editing any module:

```fish
dot-files --edit style   # or --edit modules
```

### Separator styles

| Style | Appearance |
|-------|------------|
| 1 | `█ ... █` |
| 2 | `░▒▓ ... ▓▒░` |
| 3 | Angled powerline |
| 4 | Slant powerline |
| 5 | Round powerline (default) |

Set via `~/.config/starship/style` or:

```fish
dot-files --style 5
```

### Color themes

Palettes are defined in `~/.config/starship/colors/`. The active theme is selected with
`dot-files --color`, written to `~/.config/starship/color`, and applied on rebuild.

| Theme | Palette |
| :--- | :--- |
| `moonlight` | `palettes.moonlight` |
| `catppuccin-macchiato` | `palettes.catppuccin-macchiato` |
| `catppuccin-mocha` | `palettes.catppuccin-mocha` |

### Modules

The prompt is assembled from the modules under `~/.config/starship/modules/`. Enable or disable them without editing TOML:

```fish
dot-files --list-modules
dot-files --disable-module git
dot-files --enable-module git
```

The enabled set is stored in `~/.config/starship/modules.conf` (one module per line; a leading `#` disables that module). `core` is always included, and each toggle rebuilds the prompt automatically.

## Directory icons

Directory icons are in `config/starship/modules/directory.toml`.

Starship `directory.substitutions` performs string replacement, not strict segment matching. Avoid overly generic keys such as `test` or `cache` when they could match unrelated paths.

Prefer specific entries:

```toml
".venv" = " .venv"
".pytest_cache" = "󰙨 .pytest_cache"
"node_modules" = " node_modules"
```
